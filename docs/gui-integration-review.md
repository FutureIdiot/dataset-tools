## 已确认的实现事实

### 原生 GUI (`dataset-tools`)

- `src/apps/GameInfer` 中的 Qt/C++ 应用。
- `src/libs/game-infer` 中的 ONNX 推理库。
- 接收 ONNX 模型目录，并支持 CPU 或 DirectML 选择。
- 将一个音频文件处理为一个明确选择的 MIDI 文件。
- 提供歌曲语言、分割阈值/半径、估计阈值、D3PM 步数和节拍参数；V1 中歌曲语言和
  节拍属于任务行，其他处理参数由整批共享。
- 延迟加载模型，并为后续转换保持模型存活。
- 仅报告当前音频的进度。

### Python CLI/TUI 参考 (`openvpi/GAME`)

- 使用模型检查点文件的 PyTorch 应用。
- 队列作业严格串行，并复用一个已加载的模型。
- 每个作业拥有自己的音频路径、输出目录、语言、阈值、D3PM
  参数、输出格式、文本音高设置、节拍和缓存设置；这是 Python 参考的细粒度作业模型，
  原生 Qt V1 不照搬其逐任务参数归属。
- 作业状态为 `pending`、`running`、`completed` 和 `failed`。
- 失败的作业不会停止后续作业。
- 停止表示“完成当前音频后再停止”。
- 下次运行会跳过已完成的作业；失败的作业可以重置。
- 当前 TUI 在运行期间阻止所有队列编辑。

## 冲突矩阵

| 区域 | Python CLI/TUI 参考 | 原生 Qt GUI | 集成影响 |
| --- | --- | --- | --- |
| 运行时 | Python、PyTorch、检查点文件 | C++、ONNX Runtime、模型目录 | 源代码不能直接共享。GUI 产品需要选择一种运行时。 |
| 模型打包 | 一个检查点加 Python 配置 | `config.json` 加 ONNX 模型文件 | 模型选择和验证需要原生 GUI 规则。 |
| 队列 | 有序作业对象和状态 | 一个输入/输出表单 | 需要新的 C++ 队列/控制器层和队列 UI。 |
| 参数归属 | 每个作业独立保存多项参数 | 模型/提供程序/设备与分割阈值、分割半径、估计阈值、D3PM 步数整批共享；歌曲语言和节拍按任务行保存 | 原生 V1 不采用 Python 的逐任务参数归属；批量添加复制当前歌曲语言和节拍，每行通过“参数…”只编辑输入、输出、歌曲语言和节拍；运行期间共享参数锁定。 |
| 输出 | 将 `mid`、`txt`、`csv` 写入目录 | 一个明确的 `.mid` 路径 | 必须选择 V1 输出范围和冲突策略。 |
| 加速 | PyTorch 精度和 DBCache 控制 | CPU/DirectML 提供程序和设备 | 控制项取决于运行时，不应被呈现为等价项。 |
| 停止行为 | 当前文件完成后停止 | 没有可用的取消流程；`terminate()` 为空 | V1 不应承诺立即取消。 |
| 失败行为 | 标记失败并继续 | 单文件的模态错误 | 队列失败和重试行为需要明确契约。 |
| 进度 | 每行状态加日志 | 当前文件百分比 | 队列 UI 需要同时显示当前文件进度和总体状态。 |
| 持久化 | 队列仅限当前会话 | 全局设置持久化到 INI 文件 | 队列恢复必须作为明确的产品选择。 |

## 原生 GUI 安全修复状态

1. 已改为在 GUI 线程建立转换请求，后台线程不再读取 Qt 控件。
2. 已记录实际加载的模型路径/提供程序/设备；选择变化后下次运行会重新加载。
3. 非 Windows 平台不再显示 DirectML。
4. 阈值控件范围已与 CLI 对齐为 `[0, 1)`。
5. 设置写在可执行文件旁。已安装的 macOS/Windows 位置可能不可写；平台应用配置目录
   更安全。该迁移尚未做，以避免未设计旧配置迁移就改变位置。
6. 单文件转换已增加输出目录类型检查和覆盖确认；队列会在启动前汇总检查冲突。
7. 已显式声明并链接 Qt Concurrent 构建依赖。

## 建议的 V1 设计

建议：将原生 Qt/C++ ONNX 应用保留为产品，只移植 Python TUI 的队列契约。V1
不要嵌入或启动 Python CLI。

建议的职责划分：

- 全局、运行期间锁定：模型目录、执行提供程序、设备、分割阈值、分割半径、估计阈值
  和 D3PM 步数。
- 每个作业，在批量确认或“参数…”入口中只保存：输入音频、输出 MIDI 路径、歌曲语言
  和节拍；批量添加时从主界面当前歌曲语言和节拍复制初值。
- 队列控制器：严格串行执行，加载一次模型，失败作业后继续，当前文件完成后停止，跳过已完成作业，重试失败作业。
- V1 输出：仅 MIDI。在原生引擎支持前，文本/CSV、Python 精度和 DBCache 保持延期。
- V1 编辑规则：运行期间锁定整个队列。这与已测试的 TUI 行为一致并可避免竞态；运行期间编辑待处理作业可以作为后续功能。
- 输出路径：默认在每个源文件旁生成 `<audio basename>.mid`，允许按作业编辑，并在队列启动前检测冲突。
- 队列持久化：V1 保持仅限当前会话；继续持久化全局模型、共享处理参数以及批量添加
  使用的歌曲语言/节拍默认值。

已确认并实现的 UI 组成已展开为 `docs/gui-v1-wireframe.md`：

1. 原有模型配置、处理参数、音频处理和单文件转换区域原位保留。
2. 原“转换”明确为“转换当前文件”，旁边只增加“加入队列”。
3. 队列区域新增在原界面底部并默认折叠，不取代主操作区。
4. 队列表格每行提供明确的“参数…”入口；批量确认和队列行共用参数对话框，但只允许
   修改输入、输出、歌曲语言和节拍，共享处理参数不属于任务行。
5. 当前文件继续复用原进度条，队列区域只补充总体计数和队列运行控制。

## 已确认并实现的结构决定

以下产品决定已由“按推荐方案继续”统一确认：

1. 源码基线使用官方 `Game-0605`。
2. 原生 ONNX GUI 作为最终运行时，不嵌入 Python。
3. 模型/提供程序/设备及分割阈值、分割半径、估计阈值、D3PM 步数为整批共享参数；每个
   作业只存储输入、输出、歌曲语言和节拍。批量添加复制当前歌曲语言和节拍，批量确认
   与已入队每行均提供“参数…”入口，且该入口只允许修改这四项。
4. V1 仅 MIDI。
5. 运行期间锁定整个队列。
6. 停止语义为“完成当前后停止”。
7. 队列仅限当前会话。
8. 默认在输入文件旁输出，并在启动前进行冲突检查。
9. 界面语言是独立的全局设置，支持简体中文和 English，保存选择并允许运行时切换；
   每项的模型语言参数改称“歌曲语言”，避免与界面语言混淆。

第一版已完成原生构建和无模型事件循环冒烟。队列控制器使用假处理器验证了严格串行、
失败后继续、失败重置、完成当前后停止，以及运行中禁止增删改移。中英文资源共
127 条，均已生成 `.qm` 并嵌入应用；独立探针验证 `zh_CN` 配置和关键翻译映射。

验收。模型文件当前仅用于本机试用，不纳入 Git；发布时内置模型或首次启动下载的打包
策略仍待确认。
