# GameInfer 队列 GUI V1 增量设计

当前分支已按本设计完成第一版实现；本文继续作为界面和行为契约。官方 small ONNX
模型已通过本机加载验证，真实音频也已进入上游切片流程；成功生成 MIDI 的真实音频
验收、批量音频验收与最终人工视觉验收尚未完成。

这版草案以“保留原 GUI”为首要约束。现有模型配置、处理参数、音频处理和
单文件转换流程不移位、不改成新的工作台；队列作为附加能力放在原界面下方。

## 主窗口

```text
菜单栏：[设置] → [界面语言] → [简体中文 / English]

┌ 模型配置（保留原布局）──────────────────────────────────────────────┐
│ 模型路径：[............................................] [浏览...]  │
│ 执行提供程序：[CPU]       执行设备：[默认]                          │
│ 状态：未加载 / 加载中 / 已加载 / 需要重载                          │
└─────────────────────────────────────────────────────────────────────┘

┌ 处理参数（保留原布局）──────────────────────────────────────────────┐
│ 分割阈值：[0.20]    分割半径（帧）：[2]（20.00ms）                  │
│ 估计阈值：[0.20]    采样步数：[8]                                  │
│ 歌曲语言：[默认]    节拍：[120]                                    │
└─────────────────────────────────────────────────────────────────────┘

┌ 音频处理（保留原布局）──────────────────────────────────────────────┐
│ 输入音频文件：[........................................] [浏览...]  │
│ 注意：推荐使用单声道 WAV 文件。                                    │
│ 输出 MIDI：   [........................................] [浏览...]  │
│ 进度：[██████░░░░] 60%       [转换当前文件] [加入队列]              │
└─────────────────────────────────────────────────────────────────────┘

[恢复默认值]                                [▶ 任务队列（0）]
```

原来的“转换”按钮只改成更明确的“转换当前文件”，行为保持不变。“加入队列”把
当前输入、输出、歌曲语言和节拍复制成一行任务记录；模型、执行设备以及分割/估计
阈值和 D3PM 步数仍由整批共享，不复制成每行参数。没有使用队列时，下方区域默认
折叠，窗口外观和原程序基本一致。

## 展开的队列区域

```text
┌ ▼ 任务队列（3）─────────────────────────────────────────────────────┐
│ [批量添加文件...] [参数…] [删除] [上移] [下移] [重试失败项]          │
│ ┌──┬────────┬────────────────────┬────────────────────┬──────────┬────┐ │
│ │# │状态    │输入音频            │输出 MIDI           │说明      │参数…│ │
│ ├──┼────────┼────────────────────┼────────────────────┼──────────┼────┤ │
│ │1 │已完成  │song-a.wav          │song-a.mid          │          │参数…│ │
│ │2 │运行中  │song-b.flac         │song-b.mid          │60%       │参数…│ │
│ │3 │失败    │song-c.wav          │song-c.mid          │查看错误  │参数…│ │
│ └──┴────────┴────────────────────┴────────────────────┴──────────┴────┘ │
│ 当前：song-b.flac       总体：2 / 3        [开始队列] [完成当前后停止]│
└─────────────────────────────────────────────────────────────────────┘
```

表格只展示辨认任务和判断状态所需的信息，不把整批共享的阈值、半径、估计阈值和
步数铺到每一行。每一行最后都有明确的“参数…”入口；点击后打开任务参数对话框，
只允许修改该行的输入、输出、歌曲语言和节拍，并可查看错误详情。

“批量添加文件”允许一次选择多个音频，复制当前主界面的歌曲语言和节拍，并默认在
每个输入文件旁生成同名 `.mid`。批量确认列表中的每个候选项同样提供“参数…”入口；
确认后才入队，第一次加入任务后队列区域自动展开。整批共享参数只显示当前值，不在
该对话框中编辑。

## 任务参数对话框（批量确认与队列行共用）

对话框沿用主界面的字段名称和排列，但只允许编辑四个任务字段；整批共享参数不属于
任务行：

```text
输入音频文件：[........................................] [浏览...]
输出 MIDI：   [........................................] [浏览...]

歌曲语言：[默认/zh/ja/...]
节拍 BPM：[120]

整批共享参数：模型/执行设备/分割阈值/分割半径/估计阈值/D3PM 步数（只读提示）
错误详情：仅在失败任务中显示（只读）
                                             [取消] [保存]
```

批量确认和已入队任务都必须保留“参数…”入口；保存时只更新输入、输出、歌曲语言
和节拍，不会创建或覆盖每任务的全局参数副本。

## 保留与新增的边界

| 部分 | V1 处理 |
| --- | --- |
| 模型配置 | 原位保留；队列运行期间锁定 |
| 分割阈值/分割半径/估计阈值/D3PM 步数 | 原位保留；整批共享，运行期间锁定 |
| 歌曲语言/节拍 | 原位保留；作为单文件参数和批量添加时的每任务默认值 |
| 输入/输出路径 | 原位保留；继续支持直接单文件转换 |
| 转换进度 | 原位保留；队列运行时显示当前任务进度 |
| 恢复默认值 | 原位保留；不清空已有队列任务 |
| 任务队列 | 新增在原界面底部，默认折叠 |
| 单任务编辑 | 通过对话框完成，不挤压主界面 |
| TXT/CSV、precision、DBCache | V1 不增加；原生 ONNX 引擎没有等价能力 |

## 状态与执行规则

- 状态固定为“等待、运行中、已完成、失败”。
- 模型在开始队列时加载一次，任务严格串行运行。
- 单项失败后继续下一项；失败任务可重置后重试。
- “完成当前后停止”不强行中断当前模型调用。
- 运行期间锁定模型、整批共享处理参数、单文件转换和队列编辑；每行的歌曲语言和节拍
  也不能在运行中通过“参数…”入口修改。
- 再次运行时跳过已完成任务。
- 队列仅存在于当前会话；全局模型路径、共享处理参数以及用于批量添加的歌曲语言/节拍
  默认值继续保存到设置。
- 启动队列前一次性检查重复输出和已有输出文件，统一请求覆盖确认。

## 中英文切换

- “设置 → 界面语言”提供“简体中文”和“English”。
- 界面语言与“歌曲语言”完全分开。
- 选择保存到 `QSettings`；首次启动跟随系统，非中文系统回退到 English。
- 切换后原地更新主窗口、队列、对话框、状态和错误文案，不清空任务。
- 文案使用 Qt `.ts/.qm` 翻译资源；队列内部保存状态枚举，不保存翻译后的字符串。

## 实现边界

```text
MainWindow / MainWidget（保留原单文件界面）
                 │
                 ├── JobEditorDialog（只在编辑任务时出现）
                 │
                 ▼
        InferenceQueueController
                 │
                 ▼
          Game::Game（现有引擎）
```

`InferenceQueueController` 管理任务状态、顺序、停止请求和后台执行；队列行只保存
输入、输出、歌曲语言和节拍，整批共享参数由控制器在启动时读取并在运行期间锁定。现有
`MainWidget` 继续承载模型、共享参数和单文件操作，不直接持有队列执行逻辑。
